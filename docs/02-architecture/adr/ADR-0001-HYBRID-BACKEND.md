# ADR-0001：采用混合后端与渐进式替换

- 状态：Accepted
- 日期：2026-07-30
- 决策者：项目/架构负责人角色

## 背景

候选上游同时包含 Go、Python、TypeScript 和 Java 服务。全量 Python 重写会扩大范围并丢失已实现的语义/查询能力；永久保留全部旧服务并增加 Python 代理会固化部署复杂度。

## 决策

Python 用于 `platform-api` 和分析/AI 工作进程；经准入的 Go 组件用于语义与数据核心。所有上游调用经过端口与适配器，按绞杀者模式逐步替换，目标是 3—5 个主要后端部署单元。

## 后果

- 优点：更早形成业务价值，保留高性能核心，降低一次性迁移风险；
- 代价：过渡期维护两种主要后端语言，需要强契约和可观测性；
- 控制：生成客户端、契约测试、组件退出条件和部署单元数量指标。

## 被否决方案

- 全量 Python 重写：风险和周期过高；
- 原样保留所有微服务：无法解决源码缺失、重复和运维复杂度；
- 所有请求经 Python 透传：增加延迟、故障点和大数据传输成本。
