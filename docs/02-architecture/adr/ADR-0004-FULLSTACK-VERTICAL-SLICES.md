# ADR-0004：功能按前后端纵向切片共同交付

- 状态：Accepted
- 日期：2026-07-30
- 决策者：项目/架构负责人角色

## 背景

经营决策平台的价值来自可操作的用户旅程，而不是孤立的接口或页面。若前后端分批长期交付，容易形成未被真实用户流程验证的 API、依赖模拟数据的界面、版本错配和重复联调。

## 决策

除纯基础设施或研究型工作外，每项产品功能都作为一个可独立验收的纵向切片交付。同一切片至少包含：

1. 后端领域规则、数据边界、OpenAPI 契约和权限；
2. 前端真实接口集成，以及加载、空、错误、无权限和成功状态；
3. 前后端单元/组件测试、契约检查和关键旅程联合验收；
4. 同一应用版本、同一候选制品、发布与回滚说明；
5. 需求、实现、测试、发布和验收记录的追溯关系。

前端不得用硬编码经营数据冒充可用能力。尚未实现的模块应明确显示为规划中或关闭，不产生虚假业务结论。

## 实现约束

- 控制台采用 React + TypeScript；业务/控制 API 采用 Python/FastAPI；已准入的核心数据面可由适配器复用；
- 浏览器只调用受控 Platform API，不直接耦合上游服务私有接口；
- API 先定义稳定响应模型；随着接口数量增加，引入由 OpenAPI 生成的 TypeScript 客户端并在 CI 检查漂移；
- 前端和 API 默认打包为同一版本的单一演示制品，以减少当前阶段的部署面；达到独立扩缩容或发布节奏条件后再用 ADR 拆分。

## 后果

每个功能的单次交付范围更完整，早期实现速度可能低于只做单端，但集成反馈更早、积压更少且版本证据一致。纯后端能力仍可先以技术切片建设，但在用户可见功能完成前不得标记为产品 Done。
