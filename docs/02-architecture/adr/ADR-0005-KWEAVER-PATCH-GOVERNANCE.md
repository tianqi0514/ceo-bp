# ADR-0005：锁定 KWeaver 上游并治理本地补丁

- 状态：Accepted
- 日期：2026-08-03
- 决策者：项目/架构负责人角色

## 背景

P2 真实运行时联调确认，锁定的 KWeaver Core 提交可作为核心数据面，但 BKN 初始化模型与 Vega 字段能力契约存在阻断启动的缺陷。直接改写上游检出目录会失去可重现性；整体复制上游源码又会扩大长期维护面。

## 决策

继续采用 Python Platform API 作为用户业务面和反腐层，复用 Go 核心服务。KWeaver Core 固定在 `b9b35fb245c31660127114c883e91165b42dc8f0`，仅在镜像构建阶段应用仓库内受控补丁：

1. 每个补丁必须绑定锁定提交、问题证据和回归测试；
2. 构建前执行 `git apply`，不修改共享的上游检出目录；
3. 补丁失败即终止构建，禁止模糊匹配或静默跳过；
4. 上游发布等价修复后，先验证回归测试，再删除本地补丁；
5. 用户接口仍只经过 Platform API，不把 Vega/BKN 私有契约暴露给浏览器。

当前补丁清单及验证命令见 [`components/kweaver/patches/README.md`](../../../components/kweaver/patches/README.md)。

## 运行约束

- `compose.kweaver-dev.yml` 是隔离开发栈，不是生产模板；它关闭认证和审计，并只绑定 `127.0.0.1:19006`；
- 正式环境必须启用认证、Kafka 审计、密钥托管、备份和恢复演练；
- Vega 逻辑目录通过非 root、幂等的一次性任务启用，用户 API 仅在任务成功后启动；
- 9006 共享环境在 P2 候选完成验收前保持不变。

## 后果

核心服务得以复用，Python 不重写 KWeaver 数据面；本地差异具备明确来源、自动测试和撤销路径。代价是每次上游升级必须执行补丁适配审查与真实运行时回归。
