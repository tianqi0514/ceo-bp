# 开发工作流

## 1. 迭代节奏

建议使用两周迭代和持续集成。每个迭代包含：计划、需求澄清、设计/威胁建模、实现、持续测试、演示和复盘。发布可独立于迭代，但必须通过发布门禁。

## 2. 工作项状态

`Backlog → Ready → In Progress → In Review → In Test → Ready for Release → Accepted/Done`

阻塞项标记 `Blocked` 并记录原因、责任人、开始时间和解除条件；不得用状态移动代替实际证据。

## 3. Definition of Ready（DoR）

- 有唯一需求/缺陷编号和责任人；
- 用户、业务问题、范围和非范围清楚；
- 验收标准可自动或人工验证；
- 数据口径、权限、安全、合规和 AI 风险已识别；
- 架构/API/数据库影响和依赖已分析；
- 可以在一个迭代内完成，或已拆成可独立验收的纵向切片；
- 产品、开发和测试均确认可执行。

## 4. 实现流程

1. 从最新主干创建短分支；
2. 先补契约/测试或最小失败用例，再实现；
3. 小提交，提交信息关联范围；
4. 本地执行格式化、静态检查、单元和受影响测试；
5. 发起 PR，填写影响、迁移、风险、测试和回滚；
6. 解决评审意见，禁止未经说明直接关闭关键意见；
7. CI 通过、必要批准完成后合并；
8. 在集成环境验证，更新追踪矩阵和测试记录。

产品功能遵循 [ADR-0004](../02-architecture/adr/ADR-0004-FULLSTACK-VERTICAL-SLICES.md)：在同一工作项中完成后端规则/API、前端真实接口集成、权限、测试和联合验收。基础设施工作可独立交付，但不能代替用户旅程完成。

## 5. Definition of Done（DoD）

- 验收标准全部通过并有证据；
- 代码完成独立评审，CI 通过；
- 新增行为有适当层级的自动化测试；
- 用户可见功能同时交付前端和后端，使用真实契约，不以模拟经营数据作为完成证据；
- 前端覆盖加载、空、错误、无权限和成功状态，键盘操作和响应式布局满足当前验收范围；
- 权限有允许/拒绝/跨租户测试；
- OpenAPI、前端类型/生成客户端、SDK、数据迁移、配置、运维和用户文档已同步；
- 日志、指标、追踪、审计和告警满足可运营要求；
- 无未批准的高危漏洞、密钥、许可证或数据风险；
- 性能和资源使用不低于版本门槛；
- 回滚/前滚方案已验证；
- 需求—实现—测试—发布—验收追踪完整；
- 产品或业务责任人接受结果。

任一端未完成、契约漂移或只能依赖假数据演示时，该产品功能仍为 `In Progress`，不得进入 `Accepted/Done`。

## 6. 代码评审重点

- 行为是否符合需求，边界条件和失败模式是否明确；
- 是否破坏模块边界、数据所有权或租户隔离；
- API/事件/迁移是否向后兼容且可重试；
- 是否泄露密钥、个人信息、文档内容或模型提示；
- 长任务是否幂等、可取消、可恢复；
- 指标、预测和 AI 输出是否保存版本、证据和不确定性；
- 测试是否验证行为而非只追求覆盖率数字；
- 是否引入可避免的服务、依赖或重复实现。

## 7. 紧急修复

生产 Sev-1/Sev-2 可走 hotfix，但仍需：事件编号、最小双人评审、针对性回归、发布批准、回滚方法和事后补全测试/文档。事件稳定后五个工作日内完成复盘。
