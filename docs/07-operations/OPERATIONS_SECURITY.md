# 运维、安全与合规基线

| 属性 | 值 |
|---|---|
| 文档编号 | OPS-001 |
| 版本 | 0.1.0 |
| 状态 | Baseline |
| 生效日期 | 2026-07-30 |
| 责任角色 | 运维与安全负责人 |

## 1. 环境与变更

- 开发、集成、staging、生产账号和密钥隔离；
- 基础设施与部署声明化并经评审，禁止把控制台手改作为永久状态；
- 生产使用不可变制品和受控配置，变更关联发布或事件编号；
- 管理入口、数据库和中间件不直接暴露公网；
- 高权限操作使用强认证、最小权限、限时授权和审计。

## 2. SLO 与可观测性

每条关键用户旅程定义 SLI/SLO：可用性、延迟、正确性、数据新鲜度和任务完成率。服务至少提供：

- 结构化日志和统一 trace/request/job ID；
- RED/USE 指标、业务成功率、队列积压和外部依赖指标；
- 跨 API、worker、语义和数据引擎的分布式追踪；
- 可行动告警，包含影响、排查入口、责任人和手册链接；
- 审计事件与普通调试日志分离保存。

生产 SLO 数值在试点容量和业务影响分析后批准，禁止无依据承诺。

## 3. 备份、恢复和灾备

- 明确每类数据的 RPO/RTO、备份方式、加密、保留和删除；
- 备份成功不等于可恢复，至少按季度执行恢复演练；
- 数据库、对象、索引、配置、密钥引用和审计分别制定恢复顺序；
- 向量/全文索引可由权威文档版本重建，重建过程有容量和时间预算；
- 演练记录实际耗时、数据差异、问题和改进责任人。

## 4. 安全基线

- OIDC/OAuth2 统一认证，服务身份与用户身份可区分；
- 服务端对每次请求执行租户、资源和动作授权，不信任前端隐藏；
- 传输与静态加密，密钥通过专用系统管理并轮换；
- 上传文件执行类型/大小限制、恶意内容扫描和隔离解析；
- 防 SSRF、SQL/命令/提示注入、路径穿越和不安全反序列化；
- 速率、并发、查询成本、Token 和导出配额可限制；
- SAST、依赖、镜像、IaC、密钥和许可证扫描进入 CI；
- 高危漏洞按 SLA 处理，例外有范围、补偿控制和到期日。

## 5. AI 与数据安全

- 数据按公开、内部、机密、严格机密分级，并映射到模型供应商和存储策略；
- 发送外部模型前执行权限、最小化、脱敏和合同/地域检查；
- 不用客户机密输入训练共享模型，除非有单独明确授权；
- 保存模型、提示词、工具、知识版本和输出审计，但避免在日志复制敏感正文；
- 工具调用使用允许列表、参数校验、最小权限和人工审批；
- 文档删除/撤权必须传播到对象、索引、缓存和可见引用。

## 6. 供应链与许可证

- 所有上游源码固定到提交 SHA，保留来源和修改记录；
- 依赖/镜像锁定版本与摘要，生成 SBOM 和来源证明；
- 明确 Apache、AGPL、UNLICENSED 或其他许可证边界和分发义务；
- 缺失源码、来源不明镜像、默认口令或无法重建的组件禁止进入生产；
- 项目自身许可证由负责人/法务批准后单独加入 `LICENSE`。

## 7. 事件响应

事件流程：发现 → 分级 → 控制影响 → 沟通 → 恢复 → 验证 → 复盘。Sev-1/2 事件必须保存时间线、影响、决策、证据和修复；稳定后五个工作日内完成无责复盘，行动项进入需求/风险跟踪。

安全事件优先保护证据，不擅自删除日志或轮转掉关键数据；通知义务根据合同和适用法规由授权角色判断。
