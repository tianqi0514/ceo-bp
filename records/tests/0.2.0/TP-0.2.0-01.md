## 目标与范围

验证 `platform-api` 基础接口、类型和代码质量、依赖安全、容器运行约束、9006 部署、外部访问及与共享主机现有容器的隔离。

非范围：身份权限、数据库、指标、知识库、业务知识网络、预测、性能容量、安全渗透和正式业务 UAT。

## 风险与方法

| 风险 | 方法 | 通过标准 |
|---|---|---|
| 基础接口不可用 | 单元/接口测试、内外健康检查 | 全部 200，响应模型正确 |
| 类型或代码质量退化 | Ruff + mypy strict | 0 问题 |
| 依赖已知漏洞 | 锁文件 + pip-audit | 运行依赖和已安装开发依赖无已知漏洞 |
| 容器权限过大 | Docker inspect | 非 root、只读、去 Capabilities、资源限制生效 |
| 影响其他服务 | 部署前后容器名称集哈希 | 排除 CEO-BP 后哈希一致 |
| 9006 不可达/不稳定 | 外部 20 次顺序请求 | 20/20 成功；无 5xx |
| 契约版本错误 | 读取 OpenAPI | OpenAPI 3.1，产品版本 0.2.0 |
| 服务器镜像拉取失败 | 受控离线镜像路径 | 归档与 Image ID 可校验，临时文件删除 |

## 执行套件

1. `python3 tools/validate_docs.py`；
2. `ruff check`、`mypy --strict`、`pytest + coverage`；
3. 依赖漏洞扫描；
4. Docker build、健康检查和约束检查；
5. GitHub Actions 文档与平台 API 工作流；
6. 服务器部署前检查、镜像校验、Compose 启动；
7. 主机内/外健康、OpenAPI、20 次烟雾和资源观测；
8. 部署前后共存服务比对。
